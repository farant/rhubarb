piscina

include/piscina.h · lib/piscina.interrogationes.stml

  1. possumnecan I free a single allocation from a piscina?
    No: a piscina is an arena and frees everything at once. piscina_destruere releases all of it, piscina_vacare keeps the blocks and empties them for reuse, and piscina_notare with piscina_reficere rolls back everything allocated after the mark.
    symbolum piscina_destruere piscina_vacare piscina_notare piscina_reficere
  2. quomodohow do I use temporary scratch memory in a loop without the piscina growing every iteration?
    Take a mark with piscina_notare before the temporaries and call piscina_reficere after. Everything allocated after the mark becomes invalid, but the memory is neither freed nor cleared, so a stale read usually still sees the old values and the bug is silent. Build with -DPISCINA_VENENUM=1 to fill released bytes with 0xA5 (the venenum gate does this).
    symbolum piscina_notare piscina_reficere · via tools/venenum_probare.sh
  3. quomodohow do I handle running out of memory instead of the program exiting?
    piscina_allocare is fatal: if no block can be found or created it prints the piscina's name and exits the process. piscina_conari_allocare (and _ordinatum) return NIHIL in the same situation, so the caller can recover.
    symbolum piscina_allocare piscina_conari_allocare piscina_conari_allocare_ordinatum
  4. possumnecan I put a hard cap on how much memory a piscina uses?
    Yes: piscina_generare_certae_magnitudinis makes one buffer that never grows; an allocation that does not fit is fatal through piscina_allocare or NIHIL through piscina_conari_allocare. piscina_potesne_allocare asks first. piscina_generare_dynamicum instead adds blocks (twice the initial size, or the request size plus the initial size when larger).
    symbolum piscina_generare_certae_magnitudinis piscina_potesne_allocare piscina_generare_dynamicum
  5. quidwhat alignment does piscina_allocare give, and how do I pack bytes tightly?
    Eight bytes (PISCINA_ORDINATIO_ORDINARIA), enough for every house type including pointers, i64 and f64, like malloc. For byte-only data such as text, piscina_allocare_ordinatum(piscina, mensura, I) packs with no padding. Before 2026-10-05 the default was one byte, which left wider members misaligned.
    symbolum piscina_allocare piscina_allocare_ordinatum

xar

include/xar.h · lib/xar.interrogationes.stml

  1. quomodohow do I keep pointers into an array valid while it grows?
    Use a Xar: it grows by adding segments (each twice the size of the last) and never reallocates, so a pointer from xar_addere or xar_obtinere stays valid for the life of the piscina. New elements are zeroed unless the array was created with XAR_VEXILLUM_SINE_ZEPHYRUM.
    symbolum xar_addere xar_obtinere
  2. possumnecan I treat a xar as a flat C array (memcpy, qsort, pointer arithmetic)?
    No. The segments are not contiguous: xar_obtinere(x, 0) points into the first segment only. Copy a range out with xar_copiare_ad_tabulam, sort in place with xar_ordinare, and index every element through xar_obtinere.
    symbolum xar_copiare_ad_tabulam xar_ordinare xar_obtinere
  3. quomodohow do I remove an element from the middle of a xar quickly?
    xar_removere_cum_ultimo moves the last element into the hole: O(1), but the order is not kept. At the end, xar_removere_ultimum drops the last element and xar_tollere copies it out first. There is no order-preserving removal from the middle.
    symbolum xar_removere_cum_ultimo xar_removere_ultimum xar_tollere
  4. possumnecan a xar hold more than about 33 million elements?
    Not the ordinary one: its segment table has XXIV entries (about XXXIII M elements with the default first segment of IV), and past that xar_addere prints a refusal to stderr and returns NIHIL rather than truncating silently. Create the array with xar_creare_magnum (LXIV segments) when it really is that large.
    symbolum xar_creare_magnum xar_addere
  5. curwhy must a comparator passed to xar_ordinare not allocate from the array's piscina?
    xar_ordinare is a stable merge sort whose scratch space (2n elements) comes from the array's own piscina between piscina_notare and piscina_reficere. Anything the comparator allocates there is rolled back with the scratch when the sort returns. On a fixed-size piscina with no room left it falls back to an in-place insertion sort (O(n^2), no allocation).
    symbolum xar_ordinare piscina_notare piscina_reficere
