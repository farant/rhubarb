pictor_componentia

componere pictoris (P3: prospectus, tabula, status).

pictor's view, as a Componere function for the dispensator: it reads the island, motus and the document's list of layers, and returns the component tree into the arena it is given, writing nothing. Kinds are data, so there is no type per component; the canvas's action name is computed from state (the current tool 'penicillus' gives 'penicillus.ictus'), which means handlers never branch on the tool. The pending stroke's points are copied into the canvas component so that painting reads only the tree. In October 2026 the tree grew from four nodes into an application. Layout is in cells, by dispositio, and the canvas sits one cell in from the viewport so that its border shows. The status line became a tool bar three cells high: squares for the tool, the two colours, the pattern and the size, each titled with what it should show ('color:0', 'instrumentum:aspergillum'), which is data for the figure just as the points are, and at the right end a button for the layers. A click on a square opens its palette, a dialog node added as the root's last child so that it is drawn over the canvas and hit first; its options are squares, each carrying the action that owns the attribute it sets. The layers panel is one more palette, its rows top layer first, with an insertion bar while a row is dragged. One bug it kept: the composer copied the pending points into the canvas preview whatever held the capture, so dragging a layer row drew a stray line; it now copies them only when the canvas holds it. The concrete case of 'the component is a pure projection of its state'.
