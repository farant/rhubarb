Provinciae

The sub-projects that govern folders of their own

Beside include/ and lib/ the house has fifteen folders that are projects in their own right. Each keeps its own sources, its own tests (usually a compile_probationes.sh), and most keep an orientation file (CLAUDE.md) that a new session reads first, and a phase-log of how they were built. They are listed here by layer: the parsing substrate and its clients, then the toolchain, the terminal pair, the records and the knowledge, and last the program that runs literate C. Each will deserve its own page; this one is the overview.

The parsing substrate and its clients

silva

The house's C89 parser, the fourth generation after arbor v1, arbor2 and lapifex, and the largest province. It parses any C file losslessly (comments, whitespace and preprocessor included, so a file is written back byte for byte), and it is the base of the house's tooling: the language server and the post-edit diagnostics, examen (judging C89 and the house's own rules: see all 92 codes), the formatter, renaming by meaning rather than text, nexus (who calls what), and named queries over the tree. It ships as a single amalgamated silva.c with a plain C89 silva.h, in the manner of SQLite. Since 2026-09-26 it runs on materia. Its orientation note opens with the reason it is so careful: "smoothed-over assumptions quietly shave the maximalist scope. That shaving is how the three previous parsers died."

materia

The general syntax-tree substrate, forked out of silva in August 2026 so that every language the house parses shares one engine: tokens, nodes, writing back, comparison, and the rules that keep a tree lossless. The name is scholastic: materia is what receives a forma, and a grammar is the form a general substrate receives. Each language is a "client" that declares its grammar and builds on it: the C89 front end (silva), then css, md, oratio, html, crusta and toml, in that order. The fork was sealed on 2026-09-25; generic work now lands here and owes every client's suite.

css

The first materia client after C: a CSS parser built on the total, byte-faithful css_lexema, with a registry of node kinds, an STML projection judged by a canon, selector parsing and diagnostics. Its plan B (B1 to B10), rebuilt natively on materia, closed on 2026-09-02.

md

A Markdown parser on materia (the third client), rendering HTML by composing STML rather than by printing strings. Two consumers shape it: pythonica's Prosa, for editing Markdown by structure, and citata, which checks documentation for rot. Its worklog keeps a numbered list of what STML "wanted" along the way.

oratio

A parser for natural-language prose (the fourth client), with classification of words across languages, Latin first, measured against treebanks. Its stance is written down as moderate realism: classes are earned by function, edge cases are handled by analogy, ambiguity is kept as lists at every layer, and an unknown word is a finding rather than an error. Paused since 2026-09-15. The house's Latin identifier lint (oratio/vocabula.sh), which blocks commits, lives here; partitio and partitio_aestimatio in lib/ are its scoring tools.

html

An HTML parser on materia (the fifth client), on the stateful html_lexema, with HTML5's character references from entitates_html and the html5lib project's expected trees as its oracle. Planned and built H1 to H11 in one plan, closed on 2026-09-15.

crusta

A shell parser (the sixth client; crusta is Latin for shell): POSIX sh plus the whole of bash 5.2's default syntax, total and byte-exact, projected to STML and judged by a canon, and proven against bash itself (its own deparse and bash -n) as a foreign oracle. Closed on 2026-09-16; it is how the house can reason about its own shell scripts.

toml

TOML 1.0 as the seventh client: a total, byte-exact tree, a cooked view of typed values, every error located, proven by three oracles. Planned and built in one day (2026-09-28), with no change to the substrate, which is the best evidence that materia had become general; it replaced an older lib/toml.c.

The toolchain

officina

The house's toolchain beyond parsing: a C89 compiler with its own intermediate representation (medulla, register-linear, in basic blocks), an interpreter and virtual machine (machinula), a debugger (vindex) and a flat debug format. silva is its front end, consumed only through the amalgam. It is deliberately not an LLVM competitor: it aims at REPLs, scripting and live tooling. Its IR vocabulary is sealed, and the orientation warns against coining new names casually. The legatus language-server binary is built here too.

pythonica

Not C at all: a small Python face over silva's command-line tools, so the edit scripts Claude writes touch code by NAME rather than by text. silva.Editio replaces, substitutes and inserts around named functions and types, and applies everything or nothing, with the commit gates sitting at that single write point. Standard library only, and nothing shipped depends on it: the truth stays in C.

The terminal pair

tessera

The house's terminal library, the anti-ncurses: xterm only, no terminfo, no capability queries, a cell grid with input and drawing primitives, shaped like termbox. Shipped as an amalgamated tessera.c and tessera.h. Its cells are filled by runae's widths, and through tessellatio and quadrans it can show ludus interfaces and images. A tessera is a mosaic tile.

saltuarius

The forest warden: a terminal code explorer with ranger-style columns outside and a silva-powered source view inside (token colouring, preprocessor layers, origin chains, conditional regions). Its showpiece is go-to-definition for the preprocessor: put the cursor on a token, see the chain from macro definition through include path to layer, and jump. The first true application in the monorepo, built in July 2026 as the real-world proof of both amalgams, silva's and tessera's.

Records and knowledge

gesta

The event kernel and what is built on it: the ledger (tabularium), its resident daemon (tabulariumd), the MCP servers through which Claude reads and writes it (tabularii, and fori for the forum), and frigida.sh, the cold path that writes when the daemon is down. Its truth is a committed, append-only journal (gesta/annales/tabularium.jsonl); the SQLite database is a projection rebuilt from it. Record kinds are declared as genera and judged on the way in (a page designation, for instance, is a type checked here). This is where the house keeps its open questions, parks, decisions, inventories and this book's own data.

natura

The semantic library: hand-made models that know about kinds of things (their properties, states, relations and events), written in STML as taxonomies and dictionaries (*.genera files and individuals), with species and cultivars as kinds in a Porphyrian tree. Its own description of the aim is "OOP done right": the taxonomy was what object orientation really offered, not its implementation layer. A reader in lib/ (natura) loads it, and the forum draws its census as a graph.

Running literate C

briar

Runs .thistle files, literate C89 programs: Markdown prose, STML configuration tags, raw C regions and a #! line. ./x.thistle builds once, into a cache keyed by its content, and then simply runs, so a C89 program can be written and shared like a script. Its parser is a materia client, its build writes a silex project directory and compiles that, and it can make a macOS app bundle with an icon. It has outside testers (the lapide project), whose feedback has shaped its later releases. Fran's idea of 2026-09-04; version 4 released on 2026-09-29. Its own page shows a thistle and inventories every feature, built or deferred.
