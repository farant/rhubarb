PORTAE DECLARATAE: opertura portarum ex REPOSITORIO (spec project-specs/portae-declaratae-spec.md; ledger …GGMGY94)

Declared gates: which gates a change owes, computed from the repository alone. Each gate's runner script carries its declaration as an STML annotation in a header comment: the key of the gate it runs, or 'manu' with a reason for a gate a human runs, and optionally extra paths it covers, programs its tests launch, and house binaries it owns. Everything derivable is derived and not stored: what the runner reads, executes and sources (from effectus, the summary of a script's effects), the C sources it compiles with their aedilis closures and those of the suite's tests, and any tracked path a test names in a string. From that it answers, for a list of changed paths, which gates are owed and why, which need a human, and which paths no gate covers. Written 2026-10-10 to 12, it replaced some 550 lines of Python that decided this from a ledger inventory. Two principles of Fran's drove it: what changes what a build or test does lives in the repository, and the ledger is never read to decide an outcome; and logic that runs regularly is C, with scripts as thin wrappers. Unknowns are named and never guessed: a gate whose coverage cannot be derived is owed by every change but covers nothing, so it cannot hide an uncovered path. A shadow comparison over all 9,815 tracked paths found nothing that the old answer owed and the new one does not, and about 2,000 real dependencies the ledger had never recorded, such as a gate that runs another suite's runner. One decision came out of it: the gate that tests a build tool owns that binary, so other gates that merely run bin/aedilis or bin/fabrica do not inherit its sources. Pure, with disk, git and the lexer behind a seam. The CLI is bin/fabrica portae, some fifty runner scripts carry declarations, and the owed-gates phase of a commit went from about 22 s to under 5.
