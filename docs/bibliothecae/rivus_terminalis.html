rivus_terminalis

Fons eventuum terminalis: octeti -> Eventus

The terminal as an event source, the counterpart of the window: bytes in, Eventus out, through series_terminalis and interpres_terminalis. It owns what the decoder must not: the raw buffer, the ESC and paste timeouts, the leftovers after a timeout, and the raw channels (X10 mouse, foreign CSI, bracketed paste). Pure: it neither reads nor keeps a clock; the caller hands it bytes, asks how long to wait, reports silence and pulls events, so it can be tested and replayed byte for byte. Modes are DECLARED by the application (mouse, hover, paste, focus, kitty, and path drops promoted from paste) and the source returns the bytes to write rather than writing them. Capabilities are the first event of the stream. Eventus B3, October 2026; the window and the terminal now feed the same vocabulary.
