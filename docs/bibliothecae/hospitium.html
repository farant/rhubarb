hospitium

Servus HTTP domesticus (domus hospitalis)

The house's HTTP server ('the hospitable house'), assembled from four halves already on the shelf: tcp's server socket, http's parser and serializer, router and reactor. One thread, non-blocking, keep-alive without pipelining (leftover bytes close the connection honestly). Register handlers by method and path, serve a directory (index.html, a generated listing, traversal refused after decoding), run the loop yourself one step at a time or let it run. Each connection owns an arena that is reset after every response, so everything a handler allocates lives exactly one request. Limits are configuration (connections, request and URI size, idle and header timeouts) and a full house answers 503 at once, a visible refusal instead of a silent backlog; counters for every outcome. Built 2026-07-20 after an audit, an interview and a spec; its 95 assertions passed on the first run. Used by vitrea's servant, imperium and a demo tool.
