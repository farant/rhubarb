dispensator

Ansa: derivare -> destinatio -> actio -> componere

The loop of a ludus program: derive (derivare), target (destinatio), act (actio), recompose. After EVERY dispatched event it rebuilds the component tree by calling the program's Componere function over the state (insulae and motus), into one of two ping-pong arenas so the previous tree stays valid while the next is built; painting and rasterizing happen once per frame, outside it. It owns hover (which component is under the pointer, deriving entered/left), focus and the focus stack (kept in the ephemeral island, so a restore restores them), and the quiet point: when motion settles it flushes kinetic writes to state. dispensator_pulsare feeds it time with no input, so quiet and recomposition happen when nothing arrives. A notary option records every raw event it receives, with the component it reached and the point in that component's space, for replay (eventus_notata_scribere_stml). Pure (nexus purus): the whole loop runs and is tested with no window. Used by pictor and seven probationes.
