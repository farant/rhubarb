actio

Registrum actionum NOMINATARUM

The registry of named actions. Markup NAMES its actions (actio="salvare" on a component), it never computes them, and the program registers one handler per intention; the phase comes from the event's kind. A handler gets the state repository, the motus, the target with its ascent, the matching node (possibly an ancestor of the target), the event and its context, and returns whether it consumed the event, which stops the ascent. Handlers perform no I/O: effects are returned as data. Resolution runs both ways: a name used in the tree with no handler is an error (actio_non_registratae), a handler no component names is a warning (actio_non_relatae). Duplicate and empty names are refused. Since 2026-10-08 an entry also carries a scope. When a host mounts the same application twice, each mount's handlers are merged into the host's registry under that mount's scope; a name collides only within one scope, and a component's action is looked up in the scope of the component that names it, so two scriba panes side by side can both own pagina.clavis. A merge with any collision adds nothing, and a registry can be emptied and refilled without its pointer changing, which is what a dispatcher that holds one registry needs. Used by pictor, scriba, terminale and vicus; marked nexus purus.
