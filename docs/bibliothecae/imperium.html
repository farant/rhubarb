imperium

Driving a live vitrea app from outside, in development only: JS sent into the page could act but not answer, and 'a test that cannot ask is not a test'. A command arrives over HTTP (POST /imperium with JavaScript), goes into the page, and its value comes back through the bridge; the client polls a ticket (GET /imperium/N) because hospitium's single thread must not hold a request open. Promises are awaited, since otherwise every asynchronous UI operation would return null and tests would pass falsely. Seams, all independent of the Vitrea type, for screenshots, native keys by name ('Cmd+Shift+ArrowLeft'), mouse events in page coordinates, and window size (reporting the size actually granted). It allows arbitrary code execution, so it binds 127.0.0.1 and is offered only under a -vivum flag. Its 'vivarium' gives a ready-made version to apps that have no HTTP server or RPC of their own. Used through atrium.
