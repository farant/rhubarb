fenestra

The window. Opens native macOS windows (fenestra_macos.m, Cocoa) and hands the program a TabulaPixelorum to draw into in software, RGBA8888, which it blits to the screen. Input arrives as a queue of Eventus: fenestra_perscrutari polls, and fenestra_expectare_eventus blocks until something happens, so an idle app sits near 0% CPU. Each event carries its time: the OS event's own timestamp, or a stamp taken once at the single enqueue path; a time the caller already set (replay, injection) is kept. It also injects input natively: fenestra_clavem_immittere / fenestra_claviarius and fenestra_murem_immittere / fenestra_musarius push real OS-level key and mouse events. A JavaScript dispatchEvent is untrusted (isTrusted=false) and does not even trigger :hover, so a test driven that way checks less than it seems to. The same honesty runs through the rest: fenestra_magnitudinator reports the size the window actually got, not the size asked for, and FENESTRA_RETRO opens a window without stealing focus from the user. Menus via fenestra_menu_addere. Since 2026-10-01 it is only the platform half: the input vocabulary moved to eventus.h and the pixel buffer to tabula_pixelorum.h, so code that needs neither a window nor Cocoa does not link it. Used by the apps (pictor, villa, forum, silex), atrium, concha and the auscultator/conformitas tools.
