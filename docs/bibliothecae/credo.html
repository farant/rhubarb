probationes: assertiones CREDO_* (unit tests)

The test framework: CREDO_* assertions (credo, 'I believe') that record each check with its expression, both values, file and line, then report a summary. Typed comparisons for pointers, signed and unsigned integers of each width, floats within a tolerance, chorda (equal, contains, starts, ends, empty) and literals. Two details carry history: a test that asserted NOTHING does not pass ('NIHIL PROBATUM', 2026-09-02), and CREDO_CULPA records a declared failure for an early exit, so the summary and the exit code always agree. Process assertions (CREDO_NON_RUIT 'does not crash', CREDO_NON_PENDET 'does not hang', CREDO_RUIT_CUM 'dies with this signal') run the expression in a FORKED child; they are statement macros so the expression is evaluated only in the child, and they never catch SIGSEGV in-process, since returning from a fault handler is undefined. Since 2026-10-09 a suite can be a table of named sections (credo v2; additive, the old style still runs and suites move over as they are touched). Each section gets its own arena, a set-up, a body and a tear-down that always runs, and one line in a machine-readable verdict file, written and flushed as the section ends: a suite that crashes still names what finished, and a missing last line means it crashed. CREDO_NECESSE is a fatal assertion that ends the section, in place of the guards that used to wrap the rest of a test; it is also what makes the tear-down mandatory, since resets written at the end of a section are now skipped. A second round the next day added what the first adoptions had lacked: tags from a closed vocabulary, by which sections can be skipped and are then recorded as skipped; known failures, whose reason is written in the source and which turn the suite red on the day they start passing; a fixture built once per suite, which sections may read and not change; named steps inside a scenario; a scratch directory per section, removed afterwards; and a shuffled section order with a named seed, a tool for finding hidden shared state. Its first run found ten file-scope counters in a fabrica suite that no tear-down reset, green in table order by luck. Four of the conventions are checked statically as well, as examen codes, and fabrica reads the verdict file, so a failing test is named by section and step. A converter moves the mechanical cases: of 246 old root suites it accepts 50. Used by every probatio in the house; probationes/probatio_piscina.c is the reference for the classic style.
