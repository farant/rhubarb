herbarium

specimina pressa responsorum API: captura et redditio

Pressed specimens of API responses: capture and replay. It wraps an HTTP transport; a response that is unexpected (a status at or above a threshold, or anything a judge supplied by the consumer flags) is written to disk the first time its kind is seen, and later sightings of that kind are only counted. Replay is the other half: a transport that returns stored specimens in order, so that tests run against real responses with no network. The kind of a response is its status and the skeleton of its JSON body, keys and types without values, independent of order, an array being the union of the shapes of its elements. That is Fran's rule, made after a deliberate capture showed that keying on the first element collapsed every reply beginning with a text block into one kind. Within a kind a variant is new when its body differs after digits and id-like runs are masked. What is kept is deliberately little: an allowlist of headers, never the request's headers or body, only method, host, path and the fields the caller names. Since 10-09 the guard runs before use (Fran's floor: 'is this an outlier payload that I need to save as a specimen before I do anything else'): the judge is called inside the transport wrapper, so the specimen is on disk before the consumer sees a byte. Before that, a 200 whose body was not JSON was never saved at all. Capture is on by default, under ~/.rhubarb/herbarium by API host, and a failure to capture never breaks the request. herbarium itself knows no schema and no provider. Written 2026-10-08 for vates; specimens promoted by hand, after being read, live among the test fixtures, and every one is replayed.
