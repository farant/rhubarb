pictor_documentum

Documentum pictoris = cauda ictuum

pictor's document is its stroke log. The truth is an append-only table of acta in a volumen (one SQLite file); the bitmap is a projection: the nearest checkpoint at or before the cursor, then the strokes after it. Undo and redo only move a cursor in memory. A new stroke after an undo first appends a branch marker (<ramus ab="seq"/>) and replay treats the strokes it abandons as dead, so the log is never truncated and history never lies. Every N strokes the raw RGBA is stored content-addressed (sigillum) as a checkpoint, and pictor_documentum_verificare reprojects from nothing and compares hashes. Acta v1 knows strokes (ictus: tool, colour, size, points) and branches; the other kinds in the spec are ignored for now. Opened from a volumen alone (dimensions and interval are stored in it).
