pictor_documentum

Documentum pictoris = cauda ictuum

pictor's document is its stroke log. The truth is an append-only series of acts in a volumen, and the bitmap is a projection. Since 2026-10-05 the log machinery itself (branches, checkpoints, cursor, undo, redo, verify) is historia, extracted from this library when scriba needed the same engine, and what remains here is pictor's half: pixels, how to clear them, and how to paint one act. A stroke act carries its tool, colours, size and points. The brush sweeps a disc along the line between points. The spray can (after MacPaint) scatters dots in a disc around each point, more the longer the pointer dwelt there, and the same dots at every replay because the act carries a seed. The sponge wipes a square clear. The line tool is a brush stroke of two points. A stroke can be patterned: where the classic 8x8 pattern has a bit set at the canvas position the pixel takes the first colour, elsewhere the second, and 'none' leaves the pixel alone. Colours are indices into the theme's own palette of 16. Since 10-09 the document has layers, up to 16: acts create, delete, reorder and hide them, each stroke names its layer, and the visible canvas is the composite of the theme's background and the visible layers from the bottom up. Checkpoints are then encoded by the client, and an old raw checkpoint is refused, so an old drawing replays from its acts; a test asserts that it looks identical. A pasted image becomes a new layer: fitted to the canvas, reduced to the palette by Atkinson dithering, and stored as the dithered indices, so that replay never depends on the dithering code. One volume can hold a library of drawings, each in its own namespace. One bug worth keeping: a drag off the canvas used to draw a line to the opposite edge, because signed points were cast to the house's unsigned 32-bit type. Strokes are now clipped in 64 bits before any cast, and since the bug's red state was a hang, the test first runs in a child under a hang guard.
