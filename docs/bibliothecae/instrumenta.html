Instrumenta

The tools in tools/, grouped by what they are for

About 150 files: C programs that put a command line on a library, the scripts that build and install them, the machinery of amalgams and capsules, the gates a change must pass, the generators of committed tables, oracles and probes, and a few tools for content. They are how the house is operated, as the libraries are how it is built. Each tool appears once, in the group of its main job; a linked name in the last column leads to the library it serves.

Not here: the provinces keep their own tools beside them (silva's nexus.sh, selecta.sh, renominare.sh, formator.sh, examen.sh, scribe; gesta's frigida.sh; oratio's vocabula.sh, the Latin lint; materia's oraculum_probare.sh; officina's legatus.sh), and the root holds compile_tests.sh and the other suite runners. See Provinciae.

Command-line faces of libraries

Most libraries in lib/ that are worth calling by hand have a small C program here that puts a command line on them; the binary is usually built by a matching *_struere.sh script (next group) and installed in ~/.bin. The library does the work; the tool only parses arguments and prints.

Building and installing the tools

The house builds each binary from the closure aedilis computes, not from a hand-kept list; these scripts are the per-binary recipes and their shared machinery. Two rules recur: a binary is installed into ~/.bin by copy (removing first, since macOS kills an overwritten signed binary), and the compiler flags live in exactly one place.

Gates, checks and smoke tests

What stands between a change and a commit. portae_debitae.sh answers 'which gates does this change owe, and why'; the git hooks run examen and the Latin lint; the *_fumus.sh scripts are birth gates, each first run against a planted fault (see Rubra nata in Formae). The Linux folder ports the house to two C libraries in Docker and lists the failures it expects.

Generators

Files the house does not write by hand. Each generator's output is committed with a GENERATUM marker on its first line, and fabrica regenerates and compares byte for byte (the generata gate for everything, the commit itself for what a change touches), so a stale table blocks the commit.
