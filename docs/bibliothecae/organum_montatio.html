organum_montatio

organum in ramo montare (status-plan S6): manifestum (via) + basis communis, canon generatus, elementum initiale (absentes + addita), restitutio (conservatio), domini, registratio in systematibus.

Mounting a widget on a branch of the island from its manifest: the steps that every widget's mount has in common. organum_legere_viam reads a manifest file and adds the common base; organum_ramum_parare then prepares the branch in a fixed order: the canon generated from the manifest, the initial element (the manifest's starting values plus whatever the caller adds, such as a page size), the restore of saved state, the owner table, and registration with the dismissal system. Binding a document for the reference system stays with the widget, since only it knows its document. Written 2026-10-12 (status plan S6a) by the rule of two: pictor had these steps privately, scriba became the second widget on a manifest, and the code moved here with no change in behaviour. The bundle of the three state systems (StatusSystemata) moved here from pictor's header with it. The third user came the same day and found a rule. The root of vicus is prepared the same way, but a canon attached to the root as a branch canon judges the whole tree and refused every mounted pane; a root branch now receives the repository's root canon, which leaves mounts to their own canons, and the planted fault that restored the old behaviour broke 12 of 13 vicus suites. Moving scriba onto it also showed that two scriba tests had kept loading a canon file deleted by the single-island change and had run without it, silently, ever since. Used by pictor_applicatio, scriba_applicatio and vicus.
