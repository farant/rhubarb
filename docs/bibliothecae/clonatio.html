clonatio

clonatio copy-on-write plagulae aut arboris directorii totius (pythonica S3; profilum T9: photographiae 'cp -c -R' plagulam singulam clonat, ~XIII s per photographiam).

A copy-on-write clone of a file or of a whole directory tree in one call: clonefile(2) on macOS, where APFS shares the blocks until one side writes, so a tree of any size costs no space and almost no time. One function; the destination must not exist and must be on the same volume, and on failure errno is left as the system set it. Written 2026-10-07 because of a profile: the commit machinery takes a snapshot of the tree for each shadow gate, and copying the ignored directories with cp -c -R, which clones file by file, took 13.4 s per snapshot for 71,934 files, against 2.6 s for clonefile on the directories. With the tool bin/clonare, which takes pairs so that one process serves a whole snapshot, the pythonica suite went from 422 s to 246 s. The profile also caught what no test had. git names both an ignored directory and a file inside it; creating the file's parent first made the directory's clone fail, and the fallback then skipped that directory: a silently incomplete snapshot. Only the macOS variant exists.
