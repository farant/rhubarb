pseudoterminale

infans in pseudo-terminali (aemulator-plan B3,

A child process on a pseudo-terminal: a program started from an argument vector (no shell, the house rule) on the slave side, in a new session with the pty as its controlling terminal, while the host reads and writes the master. It is a sibling of processus and not an extension of it, because a pty is one mixed stream, a long-lived child, its own size and its own signals. The library is a table of functions, which is also the test seam: read with a timeout, a write that never blocks and reports how much was taken, the window size, reaping without waiting, the master descriptor for an event loop to wait on, and a close that never leaves a zombie or an open descriptor (hang-up first, kill after a short grace). Two bridges fill the table. The posix one (openpty, fork, a reset of signal dispositions, exec) is the only file that touches system headers, and it reports a failed exec as its own error through a close-on-exec pipe, distinct from a real child exiting 127. The memory one is a scripted child with no process: it plays back given output and captures what the host writes. Written 2026-10-06 for the emulator, the header approved by Fran, who chose openpty and independence from processus. Two faults planted in it survived until the tests were fixed: /bin/sh quietly acquires a controlling terminal, so a shell-based check passed with the ioctl removed, and 'lowest free descriptor' cannot see a leak above a hole. The rule kept from it: test a child's environment with no shell in between. Owned by aemulator_hospes; terminale and the two apps create it.
