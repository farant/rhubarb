aedilis

The build's dependency engine, named after the Roman magistrate in charge of public works. Given a source file, it derives the true closure of what that program needs (which objects, which headers, which link flags) and writes it as an STML manifest, or as a bash build script that either shares cached objects or builds hermetically. It finds a header's implementation by convention (lib/<base>.c, with macos and posix variants), by the header's own <aedilis corpus="..."/> annotations, or by irregular rules in aedilis.stml, which also holds include paths, flags, framework link rules and vendored sources. It is pure: files are read only through an extractor passed in (silva in bin/aedilis, fixture tables in tests). It refuses loudly rather than guess, orders headers topologically, and checks 'pure link' promises: a file marked <aedilis nexus="purus"/> may not pull in Cocoa or any other framework.
