Bibliotheca HTTP Client

HTTP/1.1 in both directions. Client: build a request (method, URL, headers, body, timeout), execute it over tcp or tls, optionally following redirects, and read status, headers and body. Server side: a one-shot or incremental request parser with limits (1 MB request, 8 KB URI by default; exceeding them suggests 413 or 414), keep-alive and chunked detection, leftover bytes reported for pipelining, and a response serializer that owns framing (Content-Length always, except where the status forbids a body; the caller's Content-Length and Connection headers are ignored). Since 2026-09-26 a body shorter than its Content-Length is an ERROR, never a short success, reversing a July decision with RFC 9112 6.3 and the house's own words: 'a lying body is worse than an honest error'. Chunk sizes are guarded before multiplying (a hostile size used to wrap into a valid-looking body). Used by hospitium and manus; lapide's reports drove its last hardening.
