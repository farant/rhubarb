compilator

'clang -c' per thesaurum contentorum, ut bibliotheca (fabrica-6 T4; olim tools/compilator.c solum; caput Franus probavit).

'clang -c' through a content store: compile once, and afterwards copy the object out by key. There are two keys. The head key seals the working directory (-g embeds it), the compiler's identity (the real binary behind the small /usr/bin/clang trampoline, hashed once and remembered), the arguments without the output path, the source's path and bytes, and the include roots; under it is kept the list of headers the last compile really used. The full key adds the bytes of each of those headers, and one bit per header saying whether a file of the same name exists in any other include root, which is how a shadowing header is noticed although no dependency file can see it. Under the full key lies the object. A hit copies the object and never hard-links it, since a shared inode would let a later in-place writer corrupt the stored blob, and an identical destination is left untouched. Anything that is not a plain compile is handed to clang itself, so substituting it is always safe. Born 2026-10-02 as the tool bin/compilator, to retire excubitor, the old guard that judged staleness by modification time: in a four-way comparison that guard raised a false alarm on a touched header and missed a shadowing header entirely, where the store got both right. Made a library on 10-07 (slice 6) so that fabrica compiles test closures in-process. All 194 lib sources gave objects byte-identical to plain clang, and a warm run took 5 s against 21. One finding on the way: Apple clang 16 is itself non-deterministic on one house file.
