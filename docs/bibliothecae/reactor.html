Bibliotheca Reactor (Event Loop)

A single-threaded event loop over poll(): register file descriptors with callbacks for readable, writable, error or closed, add one-shot or repeating timers, then poll once (with a timeout, or none) or run until stopped. Fixed limits (1000 descriptors, 128 timers). This is the house's answer to concurrency without threads: one loop, many connections, every callback expected to return quickly. Used by hospitium; the 2026-07-20 work fixed slot reuse when a descriptor is removed and another takes its place. Since 2026-10-26 (vicus quies) it can also be driven by a loop that is not its own. A window app cannot block in poll(), so it polls the reactor without waiting and asks two things before it sleeps. reactor_mora_proxima says how long until the next timer or pending labor (0 now, -1 none). reactor_fossas_visitare lists the descriptors it waits on, the internal signal pipe included, which the window adds to its own run loop. reactor_versio_fossarum changes on every add, modify or remove, so the host re-registers only when the set changed. vicus uses it this way.
