vitrea_servus

transportus ALTER applicationis vitreae

The second transport of a vitrea app: the same capsule and the same registered methods, served over HTTP by hospitium instead of WebKit, so one application can be a window or a server. It is not a port of vitrea but the second implementation of the sender seam internuntius named from the start. The page is unchanged: as vitrea injects window.internuntius, the server injects a fetch-based twin into <head>. Only the capsule's own files are served, registered one route each, so no path can traverse the file system. Known limit, loudly: pushes from C (events) do not cross request-response HTTP, so the injected script's 'audire' throws rather than staying silent; the named fix is server-sent events. Pure C89 over hospitium, so it builds on Linux where WebKit cannot. Used by forum (August 2026).
