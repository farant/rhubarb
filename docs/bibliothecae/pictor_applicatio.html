pictor_applicatio

pictor sine scopo: volumen, documentum, insulae (canones + domini e disco), registra, dispensator (modulus 013 A4; Franus: compositio una, principalia duo)

pictor assembled with no window: the volumen, the document, the island with its canon and owners, the registries, the dispatcher. The shape is Fran's, one composition and two mains: the window app and its terminal twin call it and add only their glue, 'an application in both targets without #ifdef', and the replay test calls the same function, so it tests the real app and not a copy. Written 2026-10-03 (module 013, A4). Since the branch work of 10-05 it is in two parts: pictor_montare mounts a pictor into a given state repository on a branch of its own, with its document in a namespace of the same id, and the standalone app is a mount at the root plus a dispatcher. The mount was where the state machinery was first wired in: reading the manifest, generating canon and owner table, restoring saved state before the owners are set. Since 10-12 those steps, common to every widget, are in organum_montatio, and pictor keeps only what is pictor's: the size of the drawing and its starting focus, and binding its drawing for the reference system, since only it knows the document. It refuses to mount without its manifest, and a new canvas takes its size from the pane. For vicus, a pane can show another drawing from the volume's library or create a new one, over a cache that keeps one document object per drawing, because two objects on one history would fork its log. scriba_applicatio follows this model.
