pictor_applicatio

pictor sine scopo: volumen, documentum,

pictor assembled with no window: the volumen, the document, the island with its canon and owners, the registries, the dispatcher. The shape is Fran's, one composition and two mains: the window app and its terminal twin call it and add only their glue, 'an application in both targets without #ifdef', and the replay test calls the same function, so it tests the real app and not a copy. Written 2026-10-03 (module 013, A4). Since the branch work of 10-05 it is in two parts: pictor_montare mounts a pictor into a given state repository on a branch of its own, with its document in a namespace of the same id, and the standalone app is a mount at the root plus a dispatcher. The mount is where the newer machinery is wired in. It reads pictor's manifest and the common base through organum and generates the canon and the owner table, refusing to mount without them. It takes a bundle of the three state systems (persistence, references, popovers), restoring saved state before the owners are set and binding the document after. And a new canvas takes its size from the pane. For vicus, a pane can show another drawing from the volume's library or create a new one, over a cache that keeps one document object per drawing, because two objects on one history would fork its log. scriba_applicatio follows this model.
