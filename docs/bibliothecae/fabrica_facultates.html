Fabrica

The house build layer, and everything it can do: 84 features

fabrica answers one question about every derived file in the house: was this made from today's inputs? It was built because of a shape of failure that kept recurring: a successful build, a stale artifact, and no error. bin/manus went six weeks out of date before anyone noticed, the house had at least six private notions of "stale" (mtimes, existence checks, per-stage comparisons), and the rebake after a lib/ change was a ritual done by hand. The answer was one concept: an artifact that knows what it was built from, judged by the digests of its inputs, never by timestamps.

fabrica is a control plane for derived state. Sources, commits and the ledger belong to people; fabrica declares what should be derived from them, observes what is (iudicare), and reconciles the difference (sanare). It sits above aedilis, which stays the pure dependency oracle, and it never commits anything.

Since slice 3 it also judges checks: a gate or a test is an action whose output is a verdict, keyed by what it read, so an unchanged set of reads means the pass stands across edits and commits. Since slice 6 a test suite is a declaration, not a script: each test file is a member with its own key, and only the stale ones run.

<probationes_c> is a step: it expands into one member per matching file, each a synthetic iudicium action keyed by its source closure (from aedilis), the house binaries it runs, what it read on its last pass, and the values of its declared environment variables. Anything else in the environment is not passed in; a write outside the member's area is refused unless a <debitum_scripturae> names it (here: the two golden files the rewrite modes regenerate).

./html/compile_probationes.sh is a thin entry point (log, lock) to bin/fabrica probare probationes_html. Stale members compile through bin/compilator, link and run in their areas, printing their output; fresh ones are kept and said so (servatae K/M, with the judge's reason). Inside a member, credo runs its sections and their results come back as SECTIO records. -vis runs everything; a word after the composite runs only the members whose name contains it. The gate is the same call with -machina: pythonica reads the PROBARE record (a pass only when every member passes), not the printed text.

StrategyHowFor
regeneratiorerun the producer in scratch, compare bytes exactlycommitted generated files (amalgams, tables, snippets, capsules)

memoriaa record says these exact inputs were already verifiedactions whose inputs are provably complete, or traced
ignotanever judged; realized first, as a preconditionthings that cannot be known (an object store run blind)

Verdicts: RECENS (current), STALUM (stale, naming the input), IGNOTUM (cannot know, with the reason; never rounded to current) and NON_IUDICATUM (skipped by choice in the quick judge).
