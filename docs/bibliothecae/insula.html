Insula: status organorum in arbore UNA, porta una

Where a ludus program's state lives: an 'island', one STML tree per repository, reached only through this repository. Until 2026-10-12 there were two trees, a durable and an ephemeral one, each with its own gate; that split is gone. How long a field lives is now declared field by field in the widget's manifest (organum: persistent, transient, test-only), and what a database would hold, the documents, lives in volumes as histories. There is one gate, insula_mutare: the mutator runs on a DUPLICATE made by writing the live tree to text and reading it back in a second arena, a canon judges the result, and only then are the two swapped, so a write is all or nothing and a tree that cannot round-trip through text cannot be written. The rehydration law: after every gated write the last honest text is kept, and insula_restituere compares the tree in memory with it; a difference is a lie (someone wrote around the gate), recorded as mendacium and repaired from the honest text. Reads are global, writes are owned: an attribute can belong to one writer (zoom and pan to motus, focus to the dispensator), and a write by anyone else is refused, with the attribute, owner and offender named. Since 10-10 an owner entry may also name systems allowed to write the field (relatio, dimissio), which ended a workaround that lied in the log about who had written. Since 10-05 a repository has branches: a branch is a child of the root by kind and id, with its own canon and owners and with reads and writes relative to it, so that one store held by a host (vicus) carries several mounted applications, none of which knows where it sits. An actarius hook sees every successful write; conservatio saves through it. The doctrine was worked out in 32 web-component experiments in silicetum's laboratorium (Aug 2026) before this C89 port (Sept 2026).
