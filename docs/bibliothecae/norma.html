norma

schema valoris JSON: iudicare, exportare (norma-spec)

A schema for JSON values: state the shape once, in C, and from that one statement judge real values, export JSON Schema and, through norma_gignere, generate fake ones. Fran asked for it on 2026-10-08 in the middle of the vates work, as something like zod or ArkType whose definition doubles as a generator of mock data. His decisions: the C builder API is the source of truth, there are three modes for undeclared keys with closed as the default, and discriminated unions and nullable values are in from the first version. Nodes are built by small functions that return the node so that they nest (object and field, array, union on a tag, bounds, length in characters, choice, format), and a node may be shared between parents. Judging reports every issue and not the first, each with a named cause and a path such as $.content[2].input.n, and never quotes the value itself. The third mode, NOTANDUM, lets an undeclared key or an unknown variant pass and returns it as a note; that is what vates uses to notice that an API has grown. Misuse of the builders marks the node and is reported as a bad schema before anything is judged, and after 256 issues judging stops with a named limit. The export has a deterministic key order and no $schema key, as a tool's input schema wants. The stance is canon's, applied to JSON: closed by default, named issues, no expression language. Recursive schemas are not yet possible. Used by vates and by bin/norma.
