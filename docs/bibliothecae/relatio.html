relatio

SYSTEMA RELATIONUM (status-plan S5b): campi cum referentia ('ligamen/genus') post omnem mutationem documenti ligati (historia observata), post ligationem novam et post restitutionem verificantur; orbati per 'orbatus' …

The reference system: a field whose manifest says it refers to something in a bound document (the current layer of a drawing, say) is checked whenever that document changes, and repaired when what it points at is gone. Written 2026-10-10 (status plan S5b). The repair follows the policy the field declares: take the topmost remaining entity, remove the attribute, or leave it alone. It is written under the system's own name, so the owner check that refuses anonymous writes still holds, and undo does not revert it (Fran's choice for now). The checks run after every act, undo and redo of the document, through an observer on its historia that is registered once per history and walks every branch bound to it, so a layer deleted in one pane repairs another pane showing the same drawing. They also run at mount and at every rebinding, which covers a stale value that conservatio has just restored. The document library contributes only an ordered enumeration of ids per kind, so the widget never says what a layer is. pictor's own delete already moved the selection; the orphans this catches are the ones pictor never saw: undo and redo, another pane, rebinding, restore. Used by pictor.
