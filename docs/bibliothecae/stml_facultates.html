STML

The house's one data syntax: a tour of the syntax, and an inventory of 81 features

STML looks like XML and is the format of almost everything the house writes down that is not C: build declarations, schemas, the knowledge base's genera, the trees silva and materia project from source code, the HTML template behind the Markdown pages, the elements in a briar script. It is one syntax carrying three layers, each a pure function from a tree to a tree:

LayerDoesLibraryVerb
documenttext ⇄ tree, byte-faithfullib/stml.cstml formare
expansiontemplates filled, questions answered, lists distributedlib/stml_macros.cstml expandere
emissiontree → HTMLlib/stml_html.cstml vertere

Beside them, canon judges a document against a schema that is itself written in STML, and selectio matches CSS-style selectors. Five laws shape everything below: files are the truth and every other view is a projection; there is no expression language; every failed reference is loud; writing without the pretty-printer gives back the input byte for byte; and forms that are reserved but unbuilt are written down anyway.

Every example on this page was run through the real tools when the page was generated; what you see under each $ line is their actual output. Longer treatments: docs/stml-tutorial.md (teaches, chapter by chapter) and docs/stml-reference.md (states every rule and refusal).

1. A first document

Elements open and close like HTML. </> closes whatever is open. Attribute values are double-quoted or, for simple words, bare; a name alone is a boolean. In text, < must be written &lt;. The formatter rewrites the file into the house layout: an element with a single child takes the capture form <t(> (section 3), prose is re-wrapped, an empty pair becomes <t/>. Both spellings are the same tree.

liber.stml

<liber lingua=la publicus>
  <titulus>De Agri Cultura</titulus>
  <auctor>Cato</auctor>
  <pagina numerus="1">Est interdum praestare mercaturis rem quaerere,
    &lt;nisi&gt; tam periculosum siet.</pagina>
  <nota>brevis</>
  <vacuum></vacuum>
</liber>

$ stml formare liber.stml

<liber lingua="la" publicus>
  <titulus(> De Agri Cultura
  <auctor(> Cato
  <pagina numerus="1" (> Est interdum praestare mercaturis rem quaerere,
                         &lt;nisi&gt; tam periculosum siet.
  <nota(> brevis
  <vacuum/>
</>

2. Four kinds of text

Whitespace that contains a newline is layout; whitespace on one line is content. So in a plain element, prose can be broken across lines freely: it reads as one line. <t\> keeps the line breaks and removes the common indentation (poems, code examples). <t!> is raw: nothing inside is a tag or an entity, so code needs no escaping. A raw element can even contain its own closing tag, written <\/t>; the reader removes one backslash, the writer adds it back.

textus.stml

<exempla>
  <prosa>Haec linea
    et haec una sententia sunt.</prosa>
  <versus\>
    Arma virumque cano,
      Troiae qui primus ab oris
  </versus>
  <codex!>if (a < b && c) { x = "<b>"; }</codex>
  <scriptum!>raw text may hold <\/scriptum> itself</scriptum>
</exempla>

$ stml formare textus.stml

<exempla>
  <prosa(> Haec linea et haec una sententia sunt.
  <versus\>
    Arma virumque cano,
      Troiae qui primus ab oris
  </>
  <codex!>if (a < b && c) { x = "<b>"; }</codex>
  <scriptum!>raw text may hold <\/scriptum> itself</scriptum>
</>

3. Captures: nesting without closing tags

<t (> takes the next sibling as its child; (( and ((( take two or three. <) t> takes the previous sibling, <= t => one on each side, and <t! (> the rest of the line as raw text. They are written glued: a same-line space is content, and would be the sibling captured. HTML emission shows the resulting nesting with real close tags:

capturae.stml

<capturae>
  <sectio (>
  <titulus>Prima</titulus>
  <i>p</i><) nota>
  <i>a</i><= et =><i>b</i>
  <linea! (>  raw to the end of the line, <not> a tag
</capturae>

$ stml vertere capturae.stml

<!DOCTYPE html>
<capturae>
  <sectio>  <titulus>Prima</titulus>
</sectio>
<nota>  <i>p</i></nota>
<et>  <i>a</i><i>b</i>
</et>  <linea>  raw to the end of the line, &lt;not&gt; a tag</linea>
</capturae>

4. Attributes as elements

An attribute value cannot contain ", and cannot sensibly hold a paragraph. <@name=>…</> spells an attribute as a child element, allowed only as the first children of its element (or as a template's argument, section 6). <@name=/> is a tombstone: explicitly absent (section 7 uses one).

nexus.stml

<p>
  <a><@href=>https://exemplum.org/?q="verbum"</>nexus</a>
</p>

$ stml vertere nexus.stml

<!DOCTYPE html>
<p>
  <a href="https://exemplum.org/?q=&quot;verbum&quot;">nexus</a>
</p>

5. Fragments, and five kinds of name

<#id>…</#> is a fragment: children grouped with no element of their own. <<#id>> is a transclusion, a window onto that fragment (aliasing, not copying). The library keeps the window and resolves nothing; each consumer decides what it means, which is why vertere refuses one by name. Each kind of name has its own sigil:

6. Templates

<#@name slot="@slot"> defines a template; slots are declared on the opening tag (@slot? is optional) and used as &@slot;. <<#@name a="x">> calls it; block arguments follow the call as attribute-elements and can hold whole subtrees. COMMUTATIO chooses between arms; an optional slot may only be used inside an arm that proves it present. There is no expression language: arms compare literals, presence, tag names or patterns, nothing else.

chartae.stml

<#@charta nomen="@nomen" gradus="@gradus?" corpus="@corpus">
  <div class="charta">
    <h2>&@nomen;</h2>
    <COMMUTATIO de="&@gradus;">
      <CASUS est="alta"><p class="monitum">gradus altus</p></CASUS>
      <CASUS non-nihil><p>gradus: &@gradus;</p></CASUS>
      <CASUS nihil><p>sine gradu</p></CASUS>
    </COMMUTATIO>
    &@corpus;
  </div>
</#>
<paginae>
  <<#@charta nomen="silva" gradus="alta">><@corpus=><p>Parsator C89.</p></>
  <<#@charta nomen="materia">><@corpus=><p>Substratum arborum.</p></>
</paginae>

$ stml vertere chartae.stml

<!DOCTYPE html>
<paginae>
  <div class="charta">
    <h2>silva</h2>
<p class="monitum">gradus altus</p><p>Parsator C89.</p>  </div>

  <div class="charta">
    <h2>materia</h2>
<p>sine gradu</p><p>Substratum arborum.</p>  </div>
</paginae>

7. Lists without repeating yourself

An element whose children are anonymous fragments <>…</> dissolves into one copy per item, each inheriting the wrapper's attributes. An item's own attribute wins; a tombstone removes the inherited one.

index.stml

<ul>
  <li class="provincia">
    <>silva</>
    <><@class=>provincia nova</>briar</>
    <><@class=/>materia</>
  </li>
</ul>

$ stml vertere index.stml

<!DOCTYPE html>
<ul>
    <li class="provincia">silva</li>
    <li class="provincia nova">briar</li>
    <li>materia</li>
</ul>

8. Asking a document questions

EXEMPLAR is a pattern: an element written as you expect to find it, with $x where a value should be captured. Its answer is a set of rows. CATENA threads stages, SINE keeps the rows inside which something is absent, and PER writes its body once per row. Here: the books without a review.

Where the input comes from. A command names no target. An EXEMPLAR (or the first link of a CATENA) searches everything above it in the document, at every depth, so a <liber> anywhere above would match, not only those in the element just before it; anything below the command is invisible to it. Each later link of a CATENA takes the previous link's rows as its input and searches inside them: here SINE looks inside each <liber> the first link found. To narrow the scope, add a first stage that matches the container (<EXEMPLAR ancorata><bibliotheca/></EXEMPLAR>), or start from an earlier result with de="$x". output="$x" names the result, and something below (here PER) must consume it. Because a command sees only what is above it, a document is processed in one pass, top to bottom.

bibliotheca.stml

<bibliotheca>
  <liber id="cato"><titulus>De Agri Cultura</titulus><recensio>bona</recensio></liber>
  <liber id="varro"><titulus>Res Rusticae</titulus></liber>
  <liber id="plinius"><titulus>Naturalis Historia</titulus></liber>
</bibliotheca>
<CATENA output="$sine">
  <(><EXEMPLAR><liber id="$id"><titulus>$t</titulus></liber></EXEMPLAR>
  <(><SINE><recensio/></SINE>
</CATENA>
<ul>
  <PER congruentia="$sine"><li>&@t; (&@id;)</li></PER>
</ul>

$ stml vertere bibliotheca.stml

<!DOCTYPE html>
<bibliotheca>
  <liber id="cato"><titulus>De Agri Cultura</titulus><recensio>bona</recensio></liber>
  <liber id="varro"><titulus>Res Rusticae</titulus></liber>
  <liber id="plinius"><titulus>Naturalis Historia</titulus></liber>
</bibliotheca>
<ul><li>Res Rusticae (varro)</li><li>Naturalis Historia (plinius)</li></ul>

Also: modus (how many answers are expected), <*/> and <**> wildcards, cursus="fratrum" for runs of siblings, DIRIBITIO to dispatch by condition, TRANSPARENTIA to ignore wrappers, and <INDAGO/> to trace every stage. See the inventory below.

9. Refusals are loud

Nothing fails quietly. A template is visible only below its definition (so expansion always terminates), and calling one too early is an error with a name, a line and the template, never an empty result. The expansion layer has 31 named errors.

ordo.stml

<pagina>
  <<#@charta nomen="silva">>
</pagina>
<#@charta nomen="@nomen"><h2>&@nomen;</h2></#>

$ stml vertere ordo.stml (exit 2)

stml vertere: ordo.stml:2: FRAGMENTUM_POSTERIUS (fragmentum '@charta')

10. Contracts: canon

A canon is a schema written in STML: which elements exist, their attributes and value kinds, which children and how many, which keys must be unique or must refer to something. canones.registrum maps the house's dialects to their canons, and canon.canon describes the canon language itself. There is deliberately no expression language here either; rules that need one live in the reading program and its tests.

libri.canon

<canon dialectus="libri" versio="1">
  <elementum nomen="libri" radix="verum">
    <liberum nomen="liber" minimum="1"/>
  </elementum>
  <elementum nomen="liber">
    <attributum nomen="id" genus="nomen" necessarium="verum"/>
    <attributum nomen="annus" genus="numerus"/>
    <liberum nomen="titulus" minimum="1" maximum="1"/>
  </elementum>
  <elementum nomen="titulus" textus="verum"/>
  <unicitas nomen="libri" attributum="id" super="liber"/>
</canon>

libri.stml

<libri>
  <liber id="cato" annus="-160"><titulus>De Agri Cultura</titulus></liber>
  <liber id="cato" annus="circa 37"><titulus>Res Rusticae</titulus><auctor>Varro</auctor></liber>
  <liber><titulus>Naturalis Historia</titulus><titulus>bis</titulus></liber>
</libri>
