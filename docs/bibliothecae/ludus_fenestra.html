ludus_fenestra

glutinum fenestrae: eventus -> dispensator, quadrum -> pingere -> delineare -> praesentare

The glue between a ludus program and a real window, and on purpose the only place ludus touches the clock (fenestra_tempus_ms) or sees a window. Events go into the dispensator; each frame is a pulse, then pingere of the last tree into a per-frame arena, then delineare_mandata into the window's pixel table, then present. It measures each frame (composition, painting, rasterizing, worst frame) and prints the measurements, because the brainstorm left one optimisation conditional on them: if rasterizing dominates, rasterize frame N while frame N+1 is dispatched. ludus_fenestra_currere is the whole run loop, ending on close or after a frame count (for smoke tests) and flushing what is pending at exit. Three things changed in October 2026. The loop now waits for events when idle: it had spun without a wait since it was written, which was found when a stray pictor window sat at 100% CPU for ten minutes. A frame can be written out as a PNG (ludus_fenestra_imaginem_scribere, and -imago on the apps): the frame is a software pixel buffer, so a screenshot needs no permission and no visible window, and a frame rendered with no window at all was shown to be byte-identical to the real window's. And for living applications such as a terminal a pulse hook can be installed: the loop then waits at most 16 ms and draws only when there were events, the pulse reported a change, or the island's version has moved since the last frame drawn. A window resize is passed on in the buffer's own pixels with the scale kept. Used by pictor, scriba, terminale and vicus. Small by design: everything that can be pure lives below it.
