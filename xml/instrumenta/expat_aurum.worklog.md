# xml/instrumenta/expat_aurum.py — worklog

## 2026-11-03 — budget B2 X1: the silvestria gold, ~3x faster

Found while explaining a generata slowdown (median 34 -> 81 s): the
`xml_aurum_silvestre` action (sexta P12, in main since b9a483c1) took
46-119 s per run and ran 4-6 times per merge — once per generata gate,
and again wherever `probationes_xml` runs (it is the suite's `post`
producer), often two fabrica processes at once. ~60% of every slow
generata run.

Two costs, both serial:
- `xmllint --noout --nonet` spawned once per file (~12 ms) for ~7 930
  live files ≈ 96 s under load;
- the expat canonical form in pure Python: `_effugere` escaped one
  character at a time through a generator (~191 M characters), plus the
  handler callbacks — 40 s on its own.

Fix (output byte-identical, 7 901 lines, checked twice against the old
script on the same machine):
1. `expat_canonicum._effugere` uses `str.translate` with the same table
   (`str.maketrans(EFFUGIA)`) — C instead of a Python generator. 40 ->
   28 s for the canonical pass.
2. `expat_aurum.py`: canonical form per file in a ProcessPoolExecutor
   (chunks of 64; the spawned children inherit `-I -B`, so no
   `__pycache__` is written — that was the clone-only failure fixed in
   b9a483c1), xmllint per file in a ThreadPoolExecutor (a thread blocked
   on a child process releases the GIL). xmllint is submitted for every
   manifest line up front; missing/changed files are still skipped when
   printing. Lines are printed in manifest order, so the gold is stable.

Measured at load 15-19 on 8 cores: 69-76 s -> 21-24 s (script);
under fabrica `sanare` 23.0 s, re-judged RECENS; xml suite 12/12
(silvestria discordes 0).

regenerated by several fabrica processes) — that is the J1 ruling
