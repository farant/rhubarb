## 2026-10-31 - T11: provider client for the phase-1 finish line

Library (`include/apns.h`, `lib/apns.c`) + thin CLI (`tools/apns.c`): config from `~/.rhubarb/ios/apns.stml` (no secret in it), one blocking request over `http2_nexus` (own reactor, 30 s), the spec III.4 rule, a random well-formed device token for the retry.

- **The key never passes through this library**: the CLI reads it with `tessera_clavem_legere` (moved out of `nundinae_apple_aperire`, which now calls it - one secret-handling path, mode 0600, O_NOFOLLOW, buffers zeroed), signs with `tessera_apns_facere`, zeroes the DER, hands over only the JWT. `authorization` is sent with `numquam` set; the live suite checks Go logged the field as `(sensitive)` - the never-indexed encoding really is on the wire.
- **Rule** (pure, `apns_iudicare`): transport failure -> DEFECTUS; 200 or BadDeviceToken -> TRANSITUS; Invalid/Expired/MissingProviderToken, TopicDisallowed, BadTopic -> DEFECTUS; anything else after the all-zero token -> ITERANDUM (CLI retries once with `apns_signum_fortuitum`), otherwise TRANSITUS.
- **Preflight** (`apns -praeparare`) only *looks* at the PUSH_NOTIFICATIONS capability through `nundinae_apple_capacitas(..., creare=FALSUM)`; switching it on is the separate create-only verb `nundinae_apple -capacitas <app> PUSH_NOTIFICATIONS`, run on Fran's word.
- Local oracle: Go route `/3/device/` echoes the received apns-topic / apns-push-type / authorization in x-* response headers and answers like APNs (403 MissingProviderToken without "bearer ", 400 BadDeviceToken; `-modus iterare` makes the zero token answer DeviceTokenNotForTopic).
- Smoke 2026-10-31: `apns -probare` with an openssl-generated P-256 `.p8` against the local Go server -> 400 BadDeviceToken, TRANSIT; same key at 0644 -> refused naming chmod 600.

## 2026-11-02 - pulsus T4: apns_mittens, the server's non-blocking sender

New `include/apns_mittens.h` / `lib/apns_mittens.c`: a `PulsusMittere` on the caller's reactor. One HTTP/2 connection per ambitus (productio -> `hospes`, sandbox -> new optional `hospes_sandbox`), opened on first use, kept, reopened on the next send after its status callback says it died.

- **Memory per message, not per sender.** Each accepted message gets its own dynamic piscina (copy of the missio, headers, responses of up to 4 attempts) destroyed after its one finis. The caller's piscina holds only the struct, the key copy and fixed buffers: the provider token is signed into a fixed `character[DXII]` via a throwaway piscina (zeroed, destroyed), so a server running for months does not grow every 40 minutes. Suite "memoria": 100 messages with a 429 each -> caller piscina byte-identical.
- **Connection generations.** `http2_nexum_claudere` can fire callbacks; each nexus gets a context with a generation number, so a late "dead" from an old nexus never marks its replacement dead. The slot is cleared *before* closing the old nexus, because closing finishes its requests -> a message on its last try finishes -> pulsus's finis may send again -> re-entrant `_nexus` must see an empty slot, not a half-closed one.
- **Re-sign once, but not once per message.** On 403 Expired/InvalidProviderToken a message re-signs only if the token it used is still the current one (generation match); twenty messages failing on the same stale token cause one re-sign, not twenty (Apple throttles TooManyProviderTokenUpdates). Re-send goes through a 0 ms timer - never send from inside an http2 finis.
- **Ratio contract.** Apple's `reason` comes back bare ("BadDeviceToken"); no reason -> "status N"; anything local (transport, close, refused request) is prefixed "apns: ". The CLI needs that to tell "Apple said X" from "never reached Apple".
- **Close order.** `apns_mittentem_claudere` finishes every pending message PULSUS_DEFECTUS before returning, so it must run before whatever its finis callbacks touch (pulsus) - exemplar T5 closes the sender before `pulsus_destruere`.
- **Types moved** to `include/pulsus_missio.h` (types only, no corpus): with them in `pulsus.h` the `apns` CLI would have linked the whole communio server (volumen, cives, hospitium) through aedilis. The CLI manifest now names only the header.
- **CLI on top of the sender** (spec III.2): `apns -probare` builds a reactor + `apns_mittens` with no retries, so a live probe against Apple runs the server's own request path (headers incl. apns-priority/expiration, token signing, re-sign). Output is now `TRADITUM | SIGNUM_MORTUUM | DEFECTUS (ratio)` instead of status/apns-id. `apns_mittere` (blocking, lib/apns.c) has no caller outside `probatio_apns_vivum` now.
- Pre-existing, not changed: `apns_iudicare` calls a non-zero token with an unknown reason TRANSITUS, so `apns -probare -signum c500…` against the oracle prints TRANSIT on a 500. Fine for "is the token accepted", misleading for 5xx.
- Oracle: `/3/device/` answers by token prefix (c8 200, c410 410, c429 429 twice, c403 Expired once, c500 always 500) and prints one stderr line per request (signum, topic, push-type, priority, expiration, body); `servus_oraculi.h` gained `servum_oraculi_incipere_portu` so suite "renata" can kill the server and restart it on the same port - the sender logged `apns: connexio localhost mortua` and the next message went out on a fresh connection.
