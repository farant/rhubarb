## I. Pre-flight heals what the owed gates need

1. **All stale judges in one pass.** P3's "only refusal, once" becomes:
   heal every stale judge in `IUDICES_STRUERE` (tree-local struere
   scripts), re-judge, repeat until none is stale or a rebuild fails
   (bounded by the table size). Closes ledger …FFF0KX (1).
2. **The owed gates' tools.** For the owed gates, the union of their
   `currit` and `instrumentum` is resolved to the tree's `bin/`
   artifacts; those are judged and healed IN THE TREE through
   `bin/fabrica sanare <bin/...>` (FABRICA_AGIT=1: link only). Never an
   `institutio_*` action, never `~/.bin` (verified by hand in T1: ten
   binaries healed, `~/.bin` byte-identical). A heal that fails refuses
   with the action's log, before any gate.
3. **Generated files the commit's own formatting staled** (design
   question Q1). Today commissio formats, then refuses because a
   committed generated file is stale - the staleness it caused itself.
   Option (a): when a stale generated artifact is among the commit's own
   paths and every changed input is a path commissio just formatted,
   regenerate it through `bin/fabrica sanare` and judge again; anything
   else refuses as now. Option (b): keep refusing, but name the cause
   ("stale through commissio's own formatting") so the fix is obvious.
   Recommended: (a) - the regenerated bytes are exactly what a human
   would commit next, and the generata gate still judges them.

The resolution of `currit`/`instrumentum` to artifacts is C:
`bin/fabrica portae instrumenta -portae TSV <gates...>` prints
`INSTRUMENTUM\t<porta>\t<bin/x>\t<causa>`; pythonica calls `sanare` on
the list.

## II. INTERFACE - two kinds of gate (for Fran's approval)

The annotation gains `genus`:

```sh
# <porta titulus="vexilla" genus="praeiudicium" tegit="*.sh"/>
# <porta titulus="briar-fumus" tegit="tools/briar_struere.sh" currit="tools/briar.c"/>
```

- `praeiudicium` (pre-check): checks a property of the committed tree -
  ratchets, registries, generated == regeneration, corpus verdicts -
  without running the code under test. Initial set: vexilla,
  portae-declaratae, amalgamata, generata, examen-corpus.
- `probatio` (test, the default): runs code and judges behaviour - every
  suite and every birth test.
- an unknown `genus` is refused by gate portae-declaratae (as other bad
  annotations are).

Kind decides the PHASE and the failure policy; cost decides the order
inside a phase (III).

## III. Order and failure policy

1. pre-flight (I) - refuses before any gate;
2. **pre-checks**: all of them run, cheapest first; every failure is
   collected and reported together, then commissio refuses (one pass
   fixes them all);
3. **tests**: cheapest first, fail fast (first red refuses, as today).

Cost = median seconds of the last 10 successful runs in
`build/portae/tempora.tsv`; a gate with no history goes FIRST (it is
usually the one just written or changed); a gate whose pass will be
reused costs 0. Ordering is C: `bin/fabrica portae ordo -portae TSV
-tempora build/portae/tempora.tsv <gates...>` prints
`ORDO\t<porta>\t<genus>\t<secundae|ignota>`; commissio iterates it and
prints the order before running (`ordo portarum: vexilla 1 s, ...`).
`commissio_umbra` uses the same order.
