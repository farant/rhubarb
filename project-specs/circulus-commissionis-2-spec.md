## I. Pre-flight heals what the owed gates need

1. **All stale judges in one pass.** P3's "only refusal, once" becomes:
   heal every stale judge in `IUDICES_STRUERE` (tree-local struere
   scripts), re-judge, repeat until none is stale or a rebuild fails
   (bounded by the table size). Closes ledger …FFF0KX (1).
2. **The owed gates' tools.** For the owed gates, the union of their
   `currit` and `instrumentum` is resolved to the tree's `bin/`
   artifacts; those are judged and healed IN THE TREE through
   `bin/fabrica sanare <bin/...>` (FABRICA_AGIT=1: link only). Never an
   `institutio_*` action, never `~/.bin` (verified by hand in T1: ten
   binaries healed, `~/.bin` byte-identical). A heal that fails refuses
   with the action's log, before any gate.
3. **Stale generated files that are part of the commit** (Q1, Fran
   2026-10-14: (a), scope widened in discussion). Today commissio
   refuses with the recipe even when the staleness is its own (attempt
   2: its formatter rewrote sources after the amalgam was regenerated).
   Rule: a stale generated artifact that is AMONG THE COMMIT'S PATHS is
   regenerated through `bin/fabrica sanare` (tree-local) and judged
   again - the regenerated bytes are what the caller would commit next,
   and gate generata still judges them. A stale generated artifact NOT
   among the commit's paths still refuses, with the exact recipe:
   auto-adding it would change what is committed beyond what was asked
   (one round trip, rare).
4. **examen as a pre-flight phase.** Today examen judges staged
   `.c`/`.m` only in the git pre-commit hook (`tools/unci-git/
   pre-commit:14`), i.e. AFTER every gate - a new raw `fopen` in an
   unlisted file, or a debt line not deleted ('linea delenda', codex
   96), would refuse after the whole gate run. A phase `examen` after
   `lint` runs `./silva/examen.sh -machina` on the commit's `.c`/`.m`
   paths (per file, seconds) and refuses on REICE before any gate,
   naming every rejected file at once. The hook stays as the backstop
   for plain `git commit`.

**As built (T3):** I.3 in `_fabricam_exigere` (regenerate once, then
judge again); I.4 as phase `unci` AFTER `fabrica` (regenerated files are
judged too), calling the real hook with `UNCUS_VIAE` + the new
`UNCUS_CRIBRUM=1` - the same directory filters as the hook's git mode,
so the rules stay in the hook; it also moves `diagnostica` (.sh/.css)
before the gates. Phase order now: forma, lint, fabrica, unci, portae
debitae, instrumenta portarum, gates.

**The rule behind I** (Fran 2026-10-14): a refusal that would only print
"run X", where X is deterministic, tree-local and its result is judged
afterwards, is done by commissio itself; it refuses only where someone
must DECIDE - a real test failure, a new word, a code violation.

The resolution of `currit`/`instrumentum` to artifacts is C. **As built
(T2, departure):** no separate `portae instrumenta` command - `portae
debitae -machina` already derives exactly the owed gates, so each owed
gate's binaries follow its DEBITUM line as `BINARIUM\t<porta>\t<bin/x>
\t<ratio>` (`PortaeOpertura.binaria`: binaries the runner or its tests
EXECUTE - also when another gate owns them -, the gate's own
`instrumentum`, and `currit tools/<b>.c` -> candidate `bin/<b>`). An
existence probe (`[ -x bin/x ]`) is not an execution and adds nothing.
`bin/fabrica iudicare` ignores artifacts no action declares, so
candidates need no filter. pythonica: `_instrumenta_portarum_sanare`,
phase `instrumenta portarum` after `portae debitae`; `commissio_umbra`
does not heal yet.

## II. INTERFACE - two kinds of gate (for Fran's approval)

The annotation gains `genus`:

```sh
# <porta titulus="vexilla" genus="praeiudicium" tegit="*.sh"/>
# <porta titulus="briar-fumus" tegit="tools/briar_struere.sh" currit="tools/briar.c"/>
```

- `praeiudicium` (pre-check): checks a property of the committed tree -
  ratchets, registries, generated == regeneration, corpus verdicts -
  without running the code under test. Initial set: vexilla,
  portae-declaratae, amalgamata, generata, examen-corpus.
- `probatio` (test, the default): runs code and judges behaviour - every
  suite and every birth test.
- an unknown `genus` is refused by gate portae-declaratae (as other bad
  annotations are).

Kind decides the PHASE and the failure policy; cost decides the order
inside a phase (III).

**As built (T4):** `PortaGenus` / `PortaDeclarata.genus` in
`include/portae.h`; validated in the C reader (the house has no canon
for `<porta>` - it is the reader that refuses, by name);
`portae declaratae -machina` writes `GENUS <porta> praeiudicium` for the
non-default kind only. The five pre-checks are annotated.

## III. Order and failure policy

1. pre-flight (I) - refuses before any gate;
2. **pre-checks**: all of them run, cheapest first; every failure is
   collected and reported together, then commissio refuses (one pass
   fixes them all);
3. **tests**: cheapest first, fail fast (first red refuses, as today).

Cost = median seconds of the last 10 successful runs in
`build/portae/tempora.tsv`; a gate with no history goes FIRST (it is
usually the one just written or changed); a gate whose pass will be
reused costs 0. Ordering is C: `bin/fabrica portae ordo -portae TSV
-tempora build/portae/tempora.tsv <gates...>` prints
`ORDO\t<porta>\t<genus>\t<secundae|ignota>`; commissio iterates it and
prints the order before running (`ordo portarum: vexilla 1 s, ...`).
**As built (T5):** as above, except `commissio_umbra` keeps its own
order (departure - it runs gates in snapshot clones; left for later).
Ordering never blocks: any trouble prints a MONITUM and keeps the
given order. Measured on real history: pre-checks vexilla 1 s,
examen-corpus 180 s; tests radix 37 s, silva 165 s, pythonica 186 s.
