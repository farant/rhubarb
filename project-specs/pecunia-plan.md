# pecunia plan - money as exact decimal amounts in C89

> **For agentic workers:** execution mode is fixed by Fran's standing rule:
> INLINE, one task per turn, Fran approves each task before the next; no
> subagents. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** a foundation library `pecunia` - exact amounts (s64
ten-thousandths + ISO 4217 currency), refusing arithmetic, explicit
rounding, exact splits, exact-rate conversion, a strict canonical text
form, a display form and a lenient-by-rules input parser - with its
currency table generated from pinned ISO data.

**Architecture:** one value type (`Pecunia`, 16 bytes, no allocation)
and one named-error enum (`PecuniaVitium`) in `include/pecunia.h` /
`lib/pecunia.c`; intermediates of multiplication, conversion and
splitting in `Magnus`, rates as `Fractio`; the currency table
`lib/pecunia_monetae.c` is GENERATED by a house tool that reads the SIX
XML lists through `xml.h` and a hand supplement through `stml.h`.

**Tech stack:** C89 + latina.h; magnus, fractio, chorda,
chorda_aedificator, piscina, xml, stml, filum, sors, sigillum (fixture
pins), credo v2; oracle: Python `decimal` run ONCE to write a pinned
fixture; ISO data from SIX (ISO 4217 maintenance agency); Linux via
`tools/linux/probatio.sh` (OrbStack).

**Spec:** `project-specs/pecunia-spec.md` (quarta 0b24b94a). Read it
with this plan.

## Global constraints

- House C89 via latina.h, flags of `tools/vexilla.sh` (-pedantic -Wall
  -Wextra -Werror -Wconversion -Wsign-conversion -Wcast-qual
  -Wstrict-prototypes -Wmissing-prototypes -Wwrite-strings);
  identifiers, comments, messages Latin; never a latina.h macro as an
  identifier (every Roman numeral 0-3999 is a macro: write `X * M` for
  10000); `i32`/`i64` UNSIGNED, `s32`/`s64` signed; chorda is not
  NUL-terminated.
- **No floating point anywhere in pecunia** - not in parsing, not in
  formatting, not in intermediates.
- `PECUNIA_SCALA` = `(X * M)` = 10000; `quantitas` counts
  ten-thousandths; range +-922,337,203,685,477.5807 units.
- **Every currency name lives under `pecunia_`** (`PecuniaMoneta`,
  `pecunia_moneta_*`, `PECUNIA_MONETA_*`): the `moneta_` prefix belongs
  to `include/moneta.h` (identity mint).
- Every fallible function returns `PecuniaVitium` and leaves `exitus`
  untouched on failure; tests assert the NAMED reason, never just
  failure.
- `lib/pecunia_monetae.c` is GENERATED (line 1 `GENERATUM`): never edited
  by hand; the committed file equals the generator's output byte for
  byte (`-probare`, `generata` gate). The build never touches the
  network: ISO data is pinned under `probationes/fixa/iso4217/`.
- Fixtures are committed unchanged with their sha256 in the test header
  (RFC-fixture precedent, `probationes/probatio_blake2b.c:17-19`).
- New words pass the Latin lint (`VOCABULA_VIAE_ADDITAE="..."
  ./oratio/vocabula.sh -nova`); glossary entries allowed (never `imus`,
  never a word real in Latin or English).
- Commits via detached `silva.commissio(nuntius, viae)` with the
  absolute-path worktree guard; formator `-scribere` + `-vitia` and the
  Latin lint before; plants via `silva.planta` (compile pre-check; red,
  revert, green); a mute plant is a test gap fixed before commit; NO
  installs from the worktree; main untouched until Fran's go.

## Rulings made while planning

- **P1 - generator links house libraries.** Unlike
  `tools/runae_generare.c` (stdio only, built by bare clang), the
  pecunia generator reads XML through `xml.h` and the supplement through
  `stml.h`, so it is built with `bin/aedilis
  tools/pecunia_monetae_generare.c` (closure computed) and run from
  `build/aedilis/pecunia_monetae_generare/`. Its fabrica action follows
  the `glossae_pagina` precedent (`aedificatio.stml` ~872: script +
  sources + `manifestum` of the built tool as inputs); the exact
  `ingressus` list is settled in T1 against `bin/fabrica iudicare`.
- **P2 - table header.** `include/pecunia_monetae.h` (internal: the row
  struct is public in `pecunia.h`, this header declares the array and its
  count) so aedilis infers `lib/pecunia_monetae.c` by name - the
  `runae_tabulae.h` precedent. Consumers include only `pecunia.h`.
- **P3 - "-0.0000".** An s64 has no negative zero; the rule is about the
  WRITERS (`pecunia_ad_textum`, `pecunia_numerus`, `pecunia_formare`
  never emit a sign for zero, including zero produced by rounding a
  small negative in display) and the canonical READER (refuses
  `-0.0000`). The plant targets the writer.
- **P4 - magnitudes.** Text writers take the magnitude as `i64`
  (unsigned) so `S64` minimum prints correctly without overflow;
  `pecunia_nega` of the minimum is `SUPERFLUXUS`.
- **P5 - rounding oracle mapping** (Python `decimal`):
  `PECUNIA_PAR` = `ROUND_HALF_EVEN`, `PECUNIA_DIMIDIUM_SURSUM` =
  `ROUND_HALF_UP` (Python's is half AWAY from zero), `PECUNIA_VERSUS_
  NIHIL` = `ROUND_DOWN`, `PECUNIA_SOLUM` = `ROUND_FLOOR`,
  `PECUNIA_TECTUM` = `ROUND_CEILING`; context precision 80 (exact for
  every terminating quotient; non-terminating quotients have no ties, so
  truncation cannot flip a direction).
- **P6 - display sign placement.** With a symbol: `-$12.34`,
  accounting `($12.34)`, after: `-12.34$`. With the code: `USD -12.34`,
  accounting `USD (12.34)`, after: `-12.34 USD`. One space between code
  and number; none between symbol and number.
- **P7 - plan location** `project-specs/pecunia-plan.md` (house).
- **P8 - `Piscina*` in `pecunia_partiri` / `pecunia_dividere`.** The
  spec's sketch (II.6) omits it, but the per-part products and
  remainders are `Magnus` values and need a pool; added as the
  second-to-last parameter, like `pecunia_multiplica`.
- **P9 - where "-0.0000" can go wrong.** The spec's plant "allow
  `-0.0000` in canonical output" becomes two plants at the two places a
  sign can be wrong: the canonical READER accepting `"USD -0.0000"`
  (T5) and the display WRITER taking the sign from the unrounded value
  (USD -0.0040 shown as `"USD -0.00"`, T6). The canonical writer sees
  only an integer, which has no negative zero.

  the same second, and aedilis' `struere.sh` (`-nt`, bash 3.2, whole

## Review focus

Inputs no task's spec-derived tests would otherwise reach, most likely to
bite first:

1. **Currency codes as they really arrive:** `usd`, `Usd`, `" usd"`,
   `"usd "`, `usdd`, `us`, empty - lowercase found, everything else
   refused `MONETA_IGNOTA` (never trimmed silently).
2. **The s64 edges in text and display:** the minimum and maximum
   written canonically, as bare decimals and in display with
   accounting parentheses; reading back the extremes; one past the
   maximum refused `SUPERFLUXUS`.
3. **Splitting degenerate shapes:** `n = 0` (`RATIONES`), `n = 1` (the
   total), a zero total (all zeros), more parts than grains (USD 0.02
   into 5 -> 0.01, 0.01, 0, 0, 0), a zero ratio among positive ones
   (that part gets 0 and no leftover grain).
4. **Mixed arrays:** `pecunia_summa` over an array where one element is
   another currency -> `MONETAE_DIVERSAE`, `exitus` untouched.
5. **Human input with symbols and multi-byte separators:** `-$12.34`,
   `($12.34)`, `$12.34`, `12.34 USD`, a narrow no-break space as the
   group separator, `$-12.34` (accepted: one sign), `--12`, `$` alone,
   a code that disagrees with the given currency.

Pinned by tests: 1 -> T1 `codices`; 2 -> T5 `extrema` + T6
`extrema_formae`; 3 -> T4 `degeneres`; 4 -> T2 `summa_mixta`; 5 -> T6
`ingressus_signa`.
